# ADR-0004: CHIẾN LƯỢC RAG VECTOR SEARCH CHO CẨM NANG ẨM THỰC COOKPAD

## Trạng Thái (Status)
Đã chấp thuận (Accepted - Triển khai theo giai đoạn)

## Bối Cảnh (Context)
Hệ thống cần cung cấp hàng chục ngàn công thức nấu ăn chuẩn phong vị gia đình Việt Nam. Nếu đưa toàn bộ công thức vào Prompt của LLM, Context Window sẽ bị tràn, chi phí token cực lớn và tốc độ phản hồi rất chậm. Nếu lưu trong bảng quan hệ SQL Server truyền thống và tìm kiếm bằng từ khóa (`LIKE %từ_khóa%`), hệ thống sẽ không hiểu được ngữ nghĩa (Semantic Search) khi khách dùng từ đồng nghĩa hoặc tiếng lóng ẩm thực địa phương.

## Quyết Định (Decision)
1. **Giai đoạn MVP**: Sử dụng CSDL công thức chuẩn hóa trong bảng SQL Server (`Recipes`, `RecipeIngredients`) kết hợp In-Memory Cache để phản hồi tức thì với 50+ món ăn phổ biến nhất.
2. **Giai đoạn Enterprise**: Tích hợp kiến trúc **RAG (Retrieval-Augmented Generation)**:
   - Sử dụng mô hình `text-embedding-3-small` để vector hóa hàng trăm ngàn công thức Cookpad.
   - Lưu trữ Embeddings trong Vector Database (Qdrant / Milvus / PostgreSQL pgvector).
   - `RecipeAgent` sử dụng Hybrid Search (kết hợp Dense Vector Search và Sparse BM25) để tìm kiếm các món ăn phù hợp nhất với khẩu vị và ngân sách của khách trước khi tổng hợp mâm cơm.

## Lý Do (Reason)
- Độ chính xác tìm kiếm ngữ nghĩa đạt $>95\%$, hiểu được các yêu cầu phức tạp như *"món canh chua giải rượu nhưng không ăn được me"*.
- Tiết kiệm 80% chi phí token và giảm độ trễ phản hồi xuống dưới $1.5\text{s}$.

## Hệ Quả (Consequences)
- Cần bổ sung thêm hạ tầng Vector Database và quy trình Data Pipeline đồng bộ công thức Cookpad định kỳ.
